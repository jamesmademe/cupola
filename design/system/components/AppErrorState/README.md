# AppErrorState

The two failure leaves beneath the FaultBand: `AppErrorState`, the centred full-page state for a cold open with nothing retained, and `InlineErrorRetry`, the one-line notice for a single section.

Rendered from `lib/core/widgets/app_error_state.dart` and `lib/core/widgets/inline_error_retry.dart` by `test/design_catalog/app_error_state_catalog_test.dart`; routing from `async_value_widget.dart`. The inline messages are Unraid's, as a section that did not answer.

## How the four relate

`AsyncValueWidget` on error: a *not configured* error → NotConfiguredPlaceholder; an error over a retained value → `FaultBand.unreachable` above the last-known data at full ink, also while the provider retries or reloads; nothing retained → `AppErrorState`. A section that fails inside an otherwise loaded page → `InlineErrorRetry`. A failure whose retry already lives elsewhere → `FaultNote`.

None of them is drawn for a read whose own client was closed under it (`isClosedClientFailure`): the connection's settings changed, its provider closed the client the read was holding, and nothing was dialled. That is no failure and gets no words. `AsyncValueWidget` keeps the retained value, or shows its loading state, while the provider reads again on the rebuilt client; `AppErrorState` shows the loading state, labelled *Loading Radarr* for a screen reader, and asks again once through `onRetry`.

## AppErrorState

- Centred column, padding `space-xl`.
- A 32px glyph (26px in `.compact` — the only difference) with **no well behind it** — the Presence Rule: no red fill behind a fault. The glyph is the reason's own (`failureIcon`: `cloud_off`, `key_off`, `timer_off`, `report`, `code_off`, …) and **its tone follows the cause** (`failureTone`): nothing answered → red; a Seerr account whose session ended → blue (`logout`), the person's own step and not a fault; everything else → amber — a refused key, a 5xx, a timeout after connecting, a reply nobody can read, a certificate, a redirect, Seerr refusing its own security token twice, and a failure nobody can attribute, which is no evidence the host is silent. Walked against `surface`.
- `space-lg`, the classification's headline, naming `service:`, or without one the service the caller's `serviceName` starts with (a page may pass *Seerr issues*; the headline names Seerr), in `title-medium` 600 **in the state's tone** — the fault said once: *Radarr did not answer* (red, the only red words) · *Radarr answered but refused the key* · *Radarr was reached but did not reply in time* · *The request to Radarr did not complete* (amber) — or *the server* when no service is named. Never *Couldn't load Radarr*, and no second line repeating the state; `space-xs`; the detail in `label-small` `dim-text`, three lines max — **why, or what to do, in a plain sentence from the classification (`connectionFailureSentence`), never `error.toString()`**: *Nothing answered at the saved address. …*, *The server answered and refused the saved credentials. Check them in Settings.* (beside a remedy button it stops at the fact, *…the saved credentials.*, because the button already says what to do), *It may be busy. Retry in a moment.* A failure that carries its own verbatim sentence (`HasFailureDetail`) keeps it; a web page in the service's place reads *A web page answered at radarr.example.com instead of Radarr.*, with the path hint when the address has none; a failure nobody can attribute has nothing to add to its headline and shows no detail. `space-xl`; then the actions (below).
- **The remedy leads.** When the classification names a fix that lives in the connection's form (`FailureRemedy`, from `failureRemedy`) and `service:` names the service (or, as the fallback, `serviceName` starts with it), the fix is the button in the fault's one amber fill (`remedyFillStyle`: `tone.amber-fill` under `tone.amber-ink`) and opens the form of the connection `instanceId:` names, or the lens connection's when it names none (`ServiceRoutes.settingsForConnection`), on its Access row for a gateway with the choice it wants (`FailureRemedy.access`): *Paste the key again* (*Sign in again* for a username and password, *Paste the token again* for Plex) · *Check the address* · *Check the certificate* · *Change the address* · for a gateway in front of the service, the access it asks for: *Add a service token* (Cloudflare Access) · *Check the token* · *Add access* (a sign-in page) · *Add the password* · *Check the password*. A gateway's headline and sentence name it: *Cloudflare Access answered instead of Radarr* · *Radarr is behind Cloudflare Access. Cupola needs a service token to reach it.* *Retry* follows as a text button in ink (`primary`), `space-sm` after it, only where the same request can still succeed (`failureRetryHelps`): a refused key, an `http://` address nothing was sent to and a gateway in front of the service have no Retry; a refused sign-in keeps it, because a ban runs out. The two wrap and stay centred. Every other cause, and any state that names no service, shows *Retry* alone with an 18px `refresh` glyph when `onRetry` is set: for a fault Retry is the remedy and takes the amber fill; beside silence (red) it is the ghost button in ink (`OutlinedButton.icon`), never filled. A Seerr session that ended is not a fault: its remedy, *Sign in again* (*Signed out of Seerr* · *Sign in again to keep asking for movies and series.*), opens the connection's form in the **ink** fill (`remedyFillStyle(fault: false)`), never amber beside a blue glyph, and has no Retry beside it: no request revives a session.

## InlineErrorRetry

- Full width, margin `space-lg` × `space-sm`, padding `space-sm` vertical. No fill, no border.
- A 16px glyph walked against `surface`, in the classification's glyph and tone for the `error` that failed (`failureIcon`, `failureTone` — red only when nothing answered, amber for a refusal or any other failure that answered, and amber for a failure nobody can attribute); `space-sm`; the message `body-small` `on-surface-variant`; `space-sm`; the verb: beside silence, text button *Retry* in `primary`, minimum 56 × 44 at standard density, horizontal padding `space-sm`; for a fault, Retry is its remedy and takes the compact amber fill (`remedyFillStyle(compact: true)`: 56 × 44, padding `space-md`). A blue glyph for a Seerr session that ended, with *Sign in again* in the compact ink fill and no Retry.
- **The remedy takes Retry's place** when the classification names a fix in the connection's form, for `service:` (and `instanceId:` when the caller knows which connection the read went to; the lens's otherwise). Every call in `lib/` passes `service:` (`test/core/widgets/failure_service_guard_test.dart`); without it the notice falls back to the service the message starts by naming (`FailureRemedy.serviceNamedBy`, which `sectionFailureMessage` always satisfies), which cannot name a connection the user renamed: *Unraid answered but refused the key, so its shares are not shown.* · *Paste the key again*, in the compact amber fill: the Presence Rule gives a fault line one fill and puts it on the remedy, and amber words on the verb would spend the tone it keeps for the glyph. Where retrying can still help (a certificate, an address, a refused sign-in) both verbs stay, the amber remedy first and Retry as text in ink, on their own row under the sentence at the trailing edge, `space-xs` apart; in `.fixedHeight` the sentence then stops at two lines (the label still carries all of it). A message that names no service keeps Retry.
- The message is worded from the same classification (`sectionFailureMessage`): the headline, then what the page is without — *Unraid did not answer, so its virtual machines are not shown.* · *Unraid answered but refused the key, so its shares are not shown.*
- `.fixedHeight` locks the slot to 120px so a carousel row does not jump between loading, loaded and failed.
- A live region announced on appearance; each verb stays its own control.

## The consumer provides

For `AppErrorState`: the error and `service:`, with `instanceId:` where the screen knows the connection, and optionally `serviceName` and `onRetry`. `service:` wins over the service `serviceName` starts with, which stays the fallback for the states handed only a display name (`AsyncValueWidget`, `MediaDetailPlaceholderView`); `test/core/widgets/failure_service_guard_test.dart` fails on a call that names no service and lists the few that cannot know it, with the reason. For `InlineErrorRetry`: the message, `onRetry` and the `error` that failed — required, because a section that left it out stayed red for a refused key — and `service:`, with `instanceId:` where the screen knows the connection, which win over the service the message names. A remedy opens the form with `context.push` and reads the lens from the `ProviderScope`, both of which the app always has.

## Do / don't

- Do prefer a FaultBand over retained data whenever there is anything to retain — the last readout is what the operator came for.
- Do keep Retry beside silence a ghost in ink, never red, never filled; the one fill on a fault is the amber remedy.
- Don't offer Retry first for a cause retrying cannot fix: the remedy is the action.
- Don't use `AppErrorState` for a section inside a loaded page.
- Don't use either for a service that is not set up.
- Don't print an exception, a class name or a library's message anywhere a person reads it. Where the service is known, prefer `ServiceOfflineState.failure`: it can name the address and open the connection form.
