# MediaPosterCard

The poster as an object: a rounded plate at `level-2` that fills whatever box it is given and flies between a grid and the detail hero as one shared element.

Rendered from `lib/core/widgets/media_poster_card.dart` (with the grid it flies from, `lib/core/widgets/media_grid.dart`) by `test/design_catalog/media_poster_card_catalog_test.dart`.

- **`MediaPosterCard()`** — the rectangle. It fills its parent's constraints, so the size always comes from outside: `MediaDetailPosterRow` gives it 82 × 123. Corners are `borderRadius`, `radius-md` (12) when omitted; the only other shape input. Shadow `AppElevation.level2`, image `BoxFit.cover` through the pinned image cache (`pinnedImageCacheFor`), with no fade in or out.
- **No artwork** — no URL, an empty URL or a failed load all draw the same plate: `AppColors.plateSurface` with `fallbackIcon` at 48 in `AppColors.plateDimInk`. The plate, not the theme: artwork is not palette, so a missing poster is the same dark well on a light page and the arriving image replaces like with like. `fallbackIcon` defaults to `Icons.movie_outlined`; callers pass `Icons.person_outline`, `Icons.music_note_outlined` and similar.
- **`MediaPosterCard.circular`** — the artist and person treatment, a `ClipOval` with a circular shadow. It takes no `borderRadius`; `MediaDetailPosterRow.circular` sizes it 92 × 92.
- **Hero flight** — the card is its own `Hero`. In flight the shadow lifts from `level-2` to `level-3` and settles back (`1 − |2t − 1|` through `Curves.easeOut`), symmetric, so push and pop read the same; under Reduce Motion it flies flat at `level-2`. `MediaPosterCard.flightOnUserGestures` is `true`, and every Hero source that flies into a detail page references it, so posters also fly during the iOS swipe-back.
- **In `MediaGrid`** — the grid's tiles are `ContentCard`s under a `Hero` carrying the same tag family (`<prefix>_<id>_<index>`) and the same resting `level-2`, so the flight starts and ends on one shadow — and, with no artwork, on one plate: the tile's placeholder is this card's `plateSurface` well too. Padding `space-lg` (16) all round plus the floating nav bar's clearance at the foot on a phone (none in the desktop shell); `gridGap` (12) both ways; 2 : 3 cells. Columns come from `MediaGrid.columnsFor`: `floor((width − 32 + 12) / (130 + 12))`, never fewer than `crossAxisCount` (3). A narrower frame drops a column rather than shrinking tiles below 130 — except on a phone, where the three-column floor wins: a 390 phone answers 2 by width, 3 by the floor, and lands tiles at about 111. A 720 well draws four at about 163.
- **Status in the grid** — `statusExtractor` puts a compact `StatusBadge` in the tile's top-right corner (see ContentCard).

The consumer provides `heroTag` (unique per visual position), `imageUrl`, optional `imageHeaders`, and the `fallbackIcon`.

Semantics: in the detail hero the poster is wrapped in `ExcludeSemantics` by `MediaDetailPosterRow` — the same artwork is the backdrop and the title beside it names the region. In `MediaGrid`, when `titleExtractor` is given, each cell is one `PressableScale` button named by the title with the status's `semanticLabel` as its value (*Metropolis*, value *Downloading, 42 percent*), and the badge's own node is dropped; without a title the badge speaks for itself.
