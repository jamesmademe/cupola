# ServiceOverview

The furniture every service's Overview tab is built from: identity line, section frame, two-line row, empty note and skeleton, all derived from one `ServiceKey`.

Rendered from `lib/core/widgets/service_overview.dart`, as `lib/features/movies/presentation/radarr_overview_screen.dart` composes it, by `test/design_catalog/service_overview_catalog_test.dart`. Sixteen Overviews build on it; Radarr is the one shown. Titles, hosts and figures are sample data; section names, subtitles, links and empty copy are Radarr's real strings.

- **Page order** (Radarr): `ServiceOverviewIdentity` → `ServiceKpiPeek` (see that card; composed by the screen, not this file) → Coming up → Needs attention → Recently added → History. One scroll view. On the phone the app bar and the tab bar float above as glass bands and the page reserves `kToolbarHeight + ServiceTabBar.height` (56 + 44) at the top; in a desktop window `ServiceTabScaffold` draws the lit `ServiceTabBar.header` instead and lifts the page by the 56pt band it no longer draws. The page sits in `AmbientScaffold`, so a desktop window caps it at the content well.
- **Identity**: padding `space-sm` top, `space-lg` sides, `space-md` bottom; a wrap with `space-sm` × `space-xs` gaps. Facts `host · version` in `AppTheme.chrome` 12 / 600, `on-surface-variant`; a figure the service did not give reads `—` (the version is `—` whenever the probe did not answer, never the `v3 API` fallback). Then the status word: a 13px glyph, `space-xs`, `chrome` 12 / 600, both in the connection tone walked against `surface` (`cloud_done` *Answering*, `cloud_sync` *Checking* while the probe is in flight, and a failed probe in its classified words: `cloud_off` *Did not answer* in red only when nothing answered, `key_off` *Refused the key*, `timer_off` *Timed out* and the other faults in amber). A lens chip (padding `space-sm` × 2, `surface-container`, 1px `outline-variant`, `radius-sm`, `chrome` 11 / 600 in the accent walked for `surface`) appears only when the service has more than one connection.
- **Section** (`ServiceOverviewSection`): `SectionHeader` (`title-large` 600, subtitle `body-small` tabular in `on-surface-variant`), `space-sm`, body inset `space-lg`, then `space-lg` of air. `ServiceOverviewSection.bleed` drops the inset so a poster rail runs to the window edge. A section with a destination tab draws `Calendar →` in `label-medium` 600 in `on-surface-variant` (the secondary ink, the brand book's section link), one line; the whole header is the tap target, at least 44 tall, and switches branch with `goBranch` (outside a shell it does nothing). A section whose rows belong to several tabs (Needs attention) has no link.
- **Poster rail** (Radarr's Recently added): tiles 96 wide, `space-md` apart, the rail inset `space-lg`. Each is a `MediaPosterCard` in a 96 × 138 box (`radius-md`, `level-2`, `BoxFit.cover`; no poster → `plate-surface` with `movie_outlined` 48 in `plate-dim-ink`), `space-xs`, title `label-small` 600 `on-surface` (one line, ellipsised), year `label-small` `on-surface-variant`. The tile is one button that speaks the title with the year as its value.
- **Row** (`ServiceOverviewRow`): leading mark, `space-sm`, title in `AppTheme.data` (13 / 500): `on-surface`, or the row's tone when it states one; then 2pt and a detail in `chrome` 11 / 600 `on-surface-variant`; an optional trailing figure in `chrome` 11 / 600, capped at 132pt and ellipsised. Rows are `space-md` apart. Leading marks in use: a 58pt day column (`chrome` 11 / 600, *Today*, *Tomorrow*, then *Fri 2*), an 18px tone glyph, an 8px tone dot set 5pt down. Tones walk against `surface-container-low`.
- **Empty** (`ServiceOverviewEmpty`): `AppEmptyState.inline`: a row, not a well: nothing failed. Radarr's: *Nothing releasing this week*, *Nothing needs you*, *Nothing added yet*, *Nothing yet today*.
- **Skeleton** (`ServiceOverviewRowsSkeleton`): `rows` × (a 180 × 14 bar, `space-xs`, a 120 × 10 bar; `radius-xs`, `surface-container-high` shimmering to `surface-container`), `space-md` apart. A poster rail loads as `AppSkeleton.posterRow`. A subtitle count reads `—` while its source is loading or failed.
- **Failure**: each section is an `AsyncValueWidget.section` of its own (`.bleedSection` under `ServiceOverviewSection.bleed`). A source that never answered draws one `InlineErrorRetry` line in that section's slot, under the header that still stands: *Plex answered with an error, so what the server says about itself is not shown.*, never the page-sized `AppErrorState`; one that answered before and failed on refresh keeps its rows under a `FaultBand`, and its count keeps counting them. The readouts follow the same rule: a library that did not answer turns every figure built on it to `—` with the note *Radarr · Did not answer* (or *Radarr · Refused the key*, the classified reason), while the queue and history sections still draw.
- **Only at home** (`sectionsOrOnlyAtHome`, `ServiceOverviewOnlyAtHome`): away from home, a lens connection with no address away asks nothing, and every section would fail for the one same reason. The page says it once instead: the identity line reads `home` *Only at home* in neutral, the figure peek and the sections give way to one `InlineErrorRetry.flush` on the page column (`space-sm` top, `space-lg` sides and bottom), *Radarr has no address away, so Cupola reaches it only on your home Wi-Fi.*, with *Add an address away* in ink, which opens the connection's form on that empty field, focused. No Retry: the same request is refused until the app is home. With two connections it names the lens's (*Radarr 4K has no address away…*). A spread, not a wrapper, so the page's list still builds its sections lazily.
- **Tone**: stalled and import failed are faults (`warning`); films below cutoff are backlog (neutral). In History, grabbed is neutral and imported is `success`.

Nothing takes a colour: callers pass the `ServiceKey`, so a hue can never become text. `serviceOverviewInk(service, colorScheme)` (the secondary ink) is the one public way to ink a page's own marks the same way. Each row speaks one sentence with `·` turned into commas and silences its parts; the identity speaks *Radarr, host, version, Answering[, lens]*; a linked header speaks its title and subtitle with the hint *opens the Radarr Calendar tab*. A screen checks `isServiceConfigured` before any section is built and otherwise shows `NotConfiguredPlaceholder.forService`.

## States in the catalog

Each sheet is drawn in the dark and the light room; the desktop window with two connections.

- `RadarrOverviewScreen`: loaded, the library timed out (amber, figures read a dash), did not answer (red), away from home with no address away (one neutral line), loading.
- Text at 200%: loaded, and the library timed out.

## Do / don't

- Do pass the `ServiceKey` and let the furniture resolve every ink; never hand it a colour.
- Do let a section fail in its own slot; a retry re-asks every source that section depends on.
- Don't count inside a capped or paged response and state it as a total; a figure that did not arrive reads `—`, never 0.
- Don't paint the backlog amber: cutoff unmet and wanted are neutral.
